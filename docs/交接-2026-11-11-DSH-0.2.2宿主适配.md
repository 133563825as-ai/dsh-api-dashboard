# 交接 —— dsh-api-dashboard v1.7.3：DSH 0.2.2-rc.1 状态条落点适配

- 日期：2026-11-11
- 宿主：`@deepseek-ai/dsh` **0.2.2-rc.1**（Node 24.19.0 / Android 16 / DSHA Web GUI，真机 360×754）
- 手机壳：`dsh-web-mobile` 3.3.5（**这条必读**，落点失败的两层都是它）
- 版本：1.7.2 → **1.7.3**
- 状态：真机观感已确认（作者本人验收「可以了」）；回归测试 18 条结构断言全绿

---

## 1. 一句话

宿主 0.2.2 把 `conversation.composer.dock` 这一圈容器换了语义，插件原来「挂在 dock 槽位里」的假设**三层全废**；现在改成窄屏 portal 进**输入卡内部**，贴边改实测反算。

---

## 2. 三层根因（全部真机实测，不是推测）

真机窗口 360×754，四轮诊断读数：

| 轮次 | 落点 | 实测 | 结论 |
|---|---|---|---|
| 原样（1.7.2） | slot 锚点内 | `bar 236,691 106x34` | 被压成长条，右侧被裁 |
| ① 给 dock 加 `flex-wrap` | slot 锚点内 | 无变化 | **换行发生在 dock 层，我们在里层，够不着** |
| ② portal 到 composer dock | dock | `bar 281,685 92x28`，`span[nav=stats-ring]` | 被 `locateRing()` 当成上下文环搬走了 |
| ③ portal 到 composer stack | stack | `bar 0,724 358x28`，`gap=null` | 宽度对了，但在**卡片外面**，中间那段白是卡片底部留白 |
| ④ portal 到输入卡 | card | `bar` 整行宽，`gap→0` | 对了；再把 `--dshadb-lift` 调成 -3px 咬进 3px |

### ① slot 锚点不再是 `display:contents`

0.2.2 里 `[data-slot="conversation.composer.dock"]` 是 **`display:flex` 的真实盒子**（实测 `326×28`，`flex-wrap:nowrap`、`justify-content:flex-start`）。框架注释里的 `display:contents` 是旧行为。

更要命的是 `dsh-web-mobile` 把它整个标成统计条：

```css
[data-mobile-nav="stats"]{ height:28px!important; max-height:28px!important;
  flex-flow:row nowrap!important; overflow:hidden!important; width:100%!important }
```

胶囊是它的子节点 → 被 `nowrap` 压到 106px、被 28px + `overflow:hidden` 上下裁切。
⇒ **v1.6.6 那两条 `:has()` 规则在 0.2.2 上一条都不成立**；而且统计行本身也从 `[data-composer-stats]` 容器变成了一颗颗 `[data-composer-stat]` 药丸（单数）。

### ② 塞进 composer dock 会被当成上下文环

`dsh-web-mobile` 的 `locateRing()`：

```js
const siblings = [...dock.children].filter(c => !c.contains(stats) && !carriesComposer(c) && !c.hasAttribute('data-mobile-nav'));
const ring = siblings.find(hasProgressRing) ?? (siblings.length === 1 ? siblings[0] : undefined);
```

胶囊里没有 `circle[stroke-dasharray]`，`find` 落空 → 落到「只有一个兄弟就当环」的兜底 → 被打上 `[data-mobile-nav="stats-ring"]` 并 absolute 定位（实测 92×28 摆在 281,685）。

### ③ 落点只能是输入卡

`uV2eYG_root`（dock 的父节点）`flex-direction:column; align-items:center; padding:0 …4px`：不在统计条里、不是 dock 的子节点（环定位看不见它）、在卡片内部且紧挨统计行。

### 关键实现约束（改之前先看这里）

1. **`canPortal = !barPos && !isWideViewport()`** —— 浮动坐标是 `position:fixed`，搬进卡片会被祖先 `transform` 影响；宽屏仍走原来的 dock 布局。
2. **首帧必须还能渲染状态条** —— `portalHost === null ? barNode : createPortal(...)`，任何一步找不到宿主都回退原地，**绝不让状态条消失**。
3. **`margin-top` 不许加 `!important`** —— 行内 `margin-top` 打不过作者样式表的 `!important`（真机踩过：`mt` 写进去了、computed 仍是 `0px`，连看两轮「没变化」）。
4. **贴边必须递归钻 `display:contents`** —— 那种空壳 `getBoundingClientRect()` 恒为 `0x0`，只比「上一个兄弟」永远量不到（真机读数 `gap=null` 就是它）。
5. 几何签名缓存（`barTop:prevBottom`）别删 —— 流式输出时每次渲染都强制一次排版会卡。

## 7. 追加（同日第四轮真机反馈）：dock 换行规则在 0.2.2 上反而有害

作者反馈「钻入插件之后，下面状态那一块位置不对劲」。真机诊断读数：

```
view=bar settings=0 host=card
bar  16,726 326x24 par=div.uV2eYG_root
dock 16,677 326x52  strip 16,679 326x28  ring -
```

`dock` 高 **52px**（正常 28），`strip` 只占上面 28px —— 下面 22px 是空出来的第二行，`ContextMeter` 被挤到了那一行（环既不在统计行右侧，也不在它自己的位置）。根因就是 v1.6.6 留下的这条：

```css
[class*="_dock"]:has(> [data-slot="conversation.composer.dock"]){flex-wrap:wrap}
```

它当初的作用是「把胶囊挤到下一行」，前提是**胶囊还在 dock 里**。v1.7.3 把胶囊 portal 进输入卡之后，这条 `flex-wrap` 就只剩副作用：统计条是 `width:100%`（手机壳的 `!important`），环挤不进第一行 → 换行 → 凭空 22px 空带，环也跑到统计行下方。

**处置**：连同 `[data-slot="conversation.composer.dock"] > [data-composer-stats]{flex:0 0 100%}` 一起删除（后者等的是 0.2.2 里已不存在的容器）。删掉后 dock 恢复单行 28px，环回到统计行右侧。
`test/test-bar.mjs` 里 v1.6.6 的那两条断言已改为「必须不存在」，并写清为什么反转；`test-dock-mount-022.mjs` 另加 A7/A8 两条钉子（现共 20 条）。
