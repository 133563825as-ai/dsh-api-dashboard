## 3. 已完成的改动（两个提交）

### 3.1 `5aa3441` — v1.4.5：估算口径三处修正 + 八家价格表重核

**① 峰谷改按「事件发生时刻」计价**（`src/index.js`，影响最大）

- 旧实现只在 `summarize()` 里调 `resolveModelPrice(cfg, model)`，**没传时间戳** → 取 `Date.now()`
  → 整段历史消耗都按「打开面板那一刻」的时段计价。**DeepSeek 峰谷差整整 2 倍**，谷时跑的 token
  在峰时查看会被翻倍。而本插件的主力模型就是 `deepseek-flash`（实测会话里 100% 是它）。
- 修法：`foldUsage` 用事件自带的 **`event.time`** 判定该笔属于峰还是谷，累积进新增的 `phaseBuckets`；
  `summarize` 按峰/谷两套单价分别求和。`resolveModelPrice` 增加第 4 个参数 `phase`（`'peak'`/`'offPeak'`，传 null 才是旧行为）。
- `stateVersion` **3 → 4**。版本不匹配时框架从 `seq 0` 重放，重放时 `event.time` 仍在，所以分相结果正确；
  读不到分相的老缓存（冷路径）自动回落旧行为，不崩也不错数。
- 相关：`phaseOfModel` / `phaseAdd` / `phaseSub` / `clampMs`（后者见 §3.2）。

**② 法定节假日全天算谷时**

- 官方**英文**定价页明文：`Peak hours are 01:00-04:00 and 06:00-10:00 UTC, Monday through Friday,
  excluding Chinese public holidays ... including weekends and Chinese public holidays in full`。
  中文页只写「其余为空闲时段」，容易漏掉这半句。
- 表：`CN_HOLIDAY_RANGES`（2026 年 7 个区间，共 **33 天**），来源国务院办公厅 2025-11-04 通知
  （`gov.cn/zhengce/zhengceku/202511/content_7047091.htm`）。漏掉它这 33 天全部翻倍。
- **每年 11 月国务院办公布次年安排后必须补表**；未收录年份按「无节假日」回落（保守）。
- 调休上班的周末（2026-02-14 / 02-28 / 05-09 / 09-20 / 10-10）**不列入表内** —— 官方口径是
  `Monday through Friday` 字面，周末本身已是谷时。

**③ 缓存写入单独计价**

### 3.2 `d32f941` — 修「点设置抽搐一下」+ 刷新间隔 300 秒

**① 点设置抽搐（维护者反馈「每次点设置都稳定复现，从看板面板里面点」）**

- 根因：`openSettings` 里 `setView("bar")` 与 `setSettingsOpen(true)` **同帧生效** —— 从看板点设置时
  `DashboardDrawer` 被**当场卸载**、`SettingsModal` 同时挂载，两块全屏遮罩一换一，而看板那层
  `.dshadb_scrim` 只有入场动画（`dshadb-fadein`）、**没有出场动画** → 视觉上「啪」一下。
- 与「长按状态条打开设置不抽」完全吻合（那时 `view` 本就是 `"bar"`，`setView` 无变化）。
- 修法：打开设置时**不收看板**（设置面板照常盖在上面），关闭设置时再收。交互结果不变
  （`onClose` 回状态条、`onBack` 回看板）。

**② 刷新间隔 300 秒**

- 根因：`cordis.patch.yml` 里写死 `refreshIntervalMs: 300000`，而 `sanitizePersistedShape`
  **只夹「状态文件读出来的值」**，从 `config`（这份 patch / profile 配置）进来的值**没有任何夹取**。
  首次启动（状态文件里还没该字段）时 300000 直达 runtimeConfig —— 而 `clampRefreshSec` 上限明明是 60 秒。
- 修法：新增 `clampMs` 给 config 路径补上同一道闸门（1000~60000）；patch 值 `300000/30000` → `5000/5000`。

### 8.6 「点设置」余震（维护者刷新后反馈「还是有点抽搐」，同日第三次修）

§3.2① 只修掉了「两块全屏遮罩一换一」那一下。再查，面板自身还有**两处位移来源**，都在 `client/client.js`：

1. **两层遮罩叠加**：S1 的修法是**保留**看板那层 `.dshadb_scrim`，而设置面板又自带一层 —— 两层同为
   `rgba(0,0,0,0.35)`，叠加后总暗度 `1-(0.65)² ≈ 0.58`，打开瞬间背景在 `.15s`（`dshadb-fadein`）内渐暗。
   修法：`SettingsModal` 新增 `underScrim`，调用处传 `view !== "bar"`（即下层已有遮罩），此时把本层背景
   设为透明 —— scrim 本身保留，继续拦截点击、点空白照样关闭。
2. **面板高度随内容跳变**：`.dshadb_drawer` 是 `position:fixed; bottom:0` + `max-height:86vh`，**高度由内容决定**。
   「版本与更新」区块的结果行原来**条件渲染** —— 打开面板时它还不存在，`checkUpdate()`（`useEffect [isOpen]`）
   回来才插入约 23px。bottom 锚定 + 高度变大 = **上边缘往上跳**；本地请求 <20ms，往往还在滑入动画（`.22s`）
   期间就填充 → 观感「边滑边长」。
   修法：结果行外面套一个**固定高度槽位**（`minHeight:16px` + `marginTop:8px`），结果填进同一高度，版面零位移。

未动：`relays` / `models` 段（从看板「+中转站」「+自定义模型」进入）的列表也是异步填充（`relays.length > 0 ? 列表 : 空态`），
