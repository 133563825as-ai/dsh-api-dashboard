## 3. 本轮做了什么

### 3.1 v1.4.6 —— issue #2 三修（Qinruiy 报，09-17）

1. **余额低于预警线不再叫「异常」**：新增 `statusTextFor()`，查询正常但金额低于预警线 → **「不足」**；
   接口/解析/认证失败才叫「异常」。红灯不变。
2. **标题与卡片口径统一**：标题原本数服务端 `status==="ok"`、卡片走阈值分级 → 同屏自相矛盾。
   现在标题也走 `getLevel`，并补「需关注」汇总。
3. **余额告警真的能弹了**：旧的 `ctx.notify` / `ctx.get('webServer').notify` 在 DSH ≥ 0.1.5 上**都不存在**
   （cordis 的 `notify` 在 `ctx.reflect` 上；`dsh-host-webserver` 服务面无 `notify`），告警被 try/catch 静默吞掉。
   现改走 **DSHA App 桥** `127.0.0.1:3090/app/notify`（与 `dsh-task-notifier` 同链路，token 读 `$DSH_HOME/.bridge_token`），
   并新增 `/api-dashboard/alerts` 暴露通道状态做**可见降级**。

回归钉子：`test-v146-fixes.mjs`（20 条，分档逻辑是从 client.js **抠出来实跑**的）。

### 3.2 provider 判定改造 —— 维护者实测「一个都没识别到中转站」

两个独立的坑，都在插件侧：

- **配置位置变了（宿主侧变更）**：0.1.7 把 `settings.yaml` 的段落**迁进 profile 的 patch 层**
  （`profiles/*/cordis.patch.yml`，老文件随后写成 `settings.yaml.imported`，见 `dsh-settings` 的 "removed settings.yaml sections"）。
  插件只读老路径 → **读到空表**。现在扫全部候选位置（`profiles/*/cordis.patch.yml` 优先）并合并。
- **解析器不认 patch 形状**：新格式是 loader patch 数组里的 `- id: llm-pi-ai` + `config:` 包裹，
  而旧解析器要求顶层 `llm-pi-ai:` 键、且 `keyOf` 会跳过 `-` 开头的行。现在两种形状都认
  （providers 段的定位放宽为「段内第一个 value 为空的 providers 键」）。

判定语义按维护者要求改成**白名单制**：**默认中转站**，只有域名命中官方白名单才 official。
判定素材三级：**① provider 自写的 baseURL → ② DSH 内置目录（`@earendil-works/pi-ai` 的 `dist/providers/data/*.json`）
给的默认 baseUrl → ③ 都没有则 relay**。

> 「官方但没开放余额接口」那类（OpenAI/Claude/Gemini/MiMo/豆包/混元）**不再被错判成中转站** ——
> 本机 `xiaomi` 没写 baseURL，但目录里写明它指向 `api.xiaomimimo.com`（官方）→ 判 official。
> 铁律 9 仍然成立：**绝不按 provider 名字下结论**，名字只用来「在目录里查有没有这条」。

本机实测：`zhipu` / `xiaomi` → official；`jiyuan` / `jiyuanlvdong` / `new` / `mimov` → relay（这 4 个自动去查余额）。

⚠️ **目录读取做成了可注入参数** `computeProviderKinds(text, catalog)` —— 本机装了 pi-ai、CI 里没有，
不注入的话同一份断言会随环境给出两种结果（本轮就踩到了）。

### 3.3 v1.5.0 —— 桌面适配并入 + 音效引擎重做

**桌面/平板适配**（原 `preview/desktop` 分支，10 个预览提交）：

- ⚠️ **它从 v1.4.2 分叉，缺主线后来做的 v1.4.5 口径修正**（`CN_HOLIDAY_RANGES` / `phaseBuckets` 在它那边是 0 处）
  → **不能直接 `git merge`**（会把节假日/峰谷分相一起回退）。改用**三方合并**（base = 分叉点 `ede6c15`）只吸收其净增量：
  `client.js` / `src/index.js` **零冲突**，主线改动逐项复核在位。
- 三档形态：手机全宽 / 平板（768×1024）居中面板 / 桌面居中对话框；断点带 `(pointer:fine)` 分支 + `min-height` 兜底。
- 桌面档面板 720px + 平台卡片两列；`role="dialog"` + `aria-label`，**绝不加 `aria-modal`**
  （手机壳有 46 条以它为前缀的结构性 CSS 会重排面板）。
- 宿主侧栏竖线抑制；键盘避让 / 断点悬崖 / 内联高度退场。
- `install.sh` 支持 `DSH_DASHBOARD_REF`；CI 增加「**预发行 tag 不发 npm**」短路。
- 预览分支特有的 5 条断言（版本号须为 `X.Y.Z-desktop-preview.N`、须声明 `dsh.updateRef=preview/desktop`）
  按**正式版**形态改写（`UPDATE_REF='main'` / `PREVIEW_CHANNEL=false`），频道机制本身保留。

**音效引擎重做**（对齐上游 v0.3.8 / v0.3.10）：旧实现 `new Audio(url)` 走 media element 有三个通病 ——
① 注册进系统「正在播放」（macOS 弹 Touch Bar 播放条）；② 起播等 Promise 不跟手；③ 部分机器的网络层
（下载管理器 / IDM）拦 media 请求 → 静默无声。现在主路径是 **Web Audio**：预取 + 预解码到 `AudioBuffer`，
命中缓存即在 `pointerdown` 同一任务里 `start()`；松手音按 `RELEASE_LEAD_MS = 40` 排到「按压音结束前」起播；
Web Audio 不可用/未解码完时**回退 media element**。音效组 **2 → 4**（后两组是现有素材的交叉配对）。

## 7. 环境技巧（下次直接用）

### 7.1 推送要换节点

这台机器把 `github.com` 解析到 **`20.205.243.166`**，该地址**时通时不通**；`140.82.112/113/114/116.3` 也各自飘。
**卡住时先探测再换，别死磕一个**：

```sh
for ip in 140.82.112.3 140.82.113.3 140.82.114.3 140.82.116.3 20.205.243.166; do
  timeout 4 bash -c "echo > /dev/tcp/$ip/443" 2>/dev/null && echo "OPEN $ip" || echo "blocked $ip"
done
# 用通的节点推：
HOME=/root git -c credential.helper=store -c http.curloptResolve="github.com:443:<OPEN的IP>" push origin main
```

`credential.helper=store` 需要 `HOME`（本环境 PTC 会话里 `HOME` 可能为空，不设会报
`unable to set up default path; use --file`）。

### 7.2 拉鉴权路由自测（cookie 合成）

`/api-dashboard/*` 与首页都要会话 cookie（无 cookie → 401）。算法（`dsh-client-connection/lib/index.js`）：

```
name  = 'dsh-auth-' + base64url(sha256(authority))        // authority = '127.0.0.1:3080'
value = 'v1.' + base64url(JSON{version:1,authority,issuedAt,expiresAt}) + '.' + base64url(hmacSHA256(secret, 上面那段 base64url))
secret = ~/.dsh/.credentials.yaml → records['client-connection/browser-session'].payload.secret（base64url 解码，32 字节）
```

### 7.3 npm 有传播窗口

publish 报成功（日志里 `+ pkg@ver`）之后，registry 读数可能**几分钟内仍是旧值**。
别把传播窗口当成发布失败 —— 终据看 `registry.npmjs.org/-/npm/v1/attestations/<pkg>@<ver>` 与版本端点。

### 7.4 宿主升级后的适配检查清单（下次升级照跑）

1. `node -p "require('<dsh>/package.json').version"` 与插件的 peer 声明比对；
2. `ls <dsh>/node_modules/@deepseek-ai/ | grep dsh-client` —— 看 `dsh.client.inject` 里的模块名是否还在；
3. **启动日志** `/root/dsh-web.log` 里搜插件名，确认「加载完成」且无异常；
4. **provider 段落位置**：`~/.dsh/settings.yaml` 还是 `profiles/*/cordis.patch.yml`（0.1.7 起是后者）；
5. 官方域名白名单 `OFFICIAL_API_HOSTS` 是否还够用（新增厂商要补）。
